# 每日工作記錄表 v2.11：PWA 與 Android APK 打包說明

## 資料夾內容

| 檔案 | 用途 |
|---|---|
| `index.html` | App 本體（v2.11，已加上 manifest 連結與 Service Worker 註冊） |
| `manifest.json` | PWA 設定：名稱、圖示、主題色、截圖、捷徑 |
| `sw.js` | Service Worker：讓 App 可安裝、可離線開啟 |
| `sortable.min.js` | 拖曳排序套件 SortableJS 1.15.6（MIT 授權），放在本機，離線也能拖曳 |
| `icons/` | 一般圖示 192／512、可裁切圖示（maskable）192／512、iPhone 圖示、網頁小圖示 |
| `screenshots/` | 商店與安裝畫面用截圖（手機直式 2 張、電腦橫式 1 張） |
| `.well-known/assetlinks.json` | 網站與 APK 的驗證檔。拿到 PWABuilder 的指紋後要填寫，見第 4 步 |

> 這個資料夾裡的所有檔案（包含以「.」開頭的 `.well-known` 資料夾）都要一起上傳。

---

## 第 1 步：放到 https 網站（以 GitHub Pages 為例）

1. 在 GitHub 新增一個儲存庫，例如 `worklog`。
2. 把本資料夾**裡面的所有檔案**上傳到儲存庫的根目錄。
3. 到 **Settings → Pages**，Source 選 `Deploy from a branch`，Branch 選 `main`／`/(root)`，按 Save。
4. 約 1 分鐘後，網址會是：`https://您的帳號.github.io/worklog/`
5. 用 Android 的 Chrome 打開，確認 App 正常、語音可以用。

> **重要：`.well-known` 資料夾的位置**
> Android 只會去「網域根目錄」找驗證檔：`https://您的帳號.github.io/.well-known/assetlinks.json`
> 如果 App 放在子路徑（例如 `/worklog/`），還要另外建一個名為 `您的帳號.github.io` 的儲存庫，把 `.well-known/assetlinks.json` 放在那裡。
> 少了這一步 APK 仍然可以用，只是畫面最上方會多出一條網址列。

## 第 2 步：用 PWABuilder 檢查

1. 打開 https://www.pwabuilder.com
2. 貼上您的網址，按 **Start**。
3. 確認 Manifest 和 Service Worker 都顯示通過（綠色）。

## 第 3 步：產生 Android APK

1. 按 **Package For Stores**，選 **Android → Generate Package**。
2. 建議設定：
   - **Package ID**：`io.github.您的帳號.worklog`（英文小寫，之後不能更改）
   - **App name**：每日工作記錄表
   - **Launcher name**：工作記錄
   - **Version**：`1.0.0`，Version code：`1`
   - **Signing key**：選 **Create new**（第一次）
3. 下載 zip，裡面會有：
   - `*.apk`：可以直接傳到手機安裝測試
   - `*.aab`：上架 Google Play 時使用
   - `signing.keystore` 與 `signing-key-info.txt`：**務必妥善保存**，之後更新 App 都要用同一把金鑰
   - `assetlinks.json`：PWABuilder 已經幫您填好指紋的版本

## 第 4 步：填寫 assetlinks.json（去掉網址列）

用 PWABuilder 下載的 `assetlinks.json` 取代本資料夾的 `.well-known/assetlinks.json`，再上傳到網域根目錄（見第 1 步的「重要」說明）。
上傳後可以在這裡檢查：
`https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://您的帳號.github.io&relation=delegate_permission/common.handle_all_urls`

## 第 5 步：安裝到手機

1. 把 `.apk` 傳到手機（LINE、Email 或 Google 雲端硬碟都可以）。
2. 點開安裝，手機提示「允許安裝不明來源的應用程式」時，選擇允許。
3. 第一次按 🎤 或 ➕ 時，請允許麥克風權限。

## 備份與還原（v2.4 起）

- **☁️ 備份到 Google Drive**：使用手機的「分享」功能，在分享選單選「**雲端硬碟**」，再選擇 Google 帳號和資料夾，就能直接存進 Google Drive，不需要任何設定。備份檔是 `.txt`，內容是 JSON；Android 的分享功能不接受 `.json` 檔，所以改用 `.txt`。電腦或不支援分享的瀏覽器會自動改為下載。
- **📥 下載備份檔到手機**：存成 `.json` 檔，放在手機的「下載」資料夾。
- **📂 從備份檔還原（可選 Drive）**：在檔案選擇畫面點左上角 ☰，選「**雲端硬碟**」，就能直接選 Google Drive 裡的備份檔，`.txt` 或 `.json` 都可以。
- **📋 複製備份文字／📝 貼上文字還原**：以上方式都不能用時的備用方案。
- 超過 7 天沒備份，畫面上方會出現提醒，按「立即備份」會優先使用 Google Drive 分享。

## 完成的任務自動排到最下方（v2.5 起）

- 主任務、次任務、孫任務只要**打勾完成**，就會自動移到**同一層的最下方**。
- **取消打勾**時，會移回未完成任務的最後面，也就是已完成任務的上方。
- 還是可以用 ☰ 手動拖曳調整順序。

## 拖曳搬移，可以跨層級（v2.9 起）

按住左側 ☰ 拖曳，可以在同一層排序，也可以搬到不同層級：

| 放到哪裡 | 會變成 |
|---|---|
| 主任務之間 | 主任務 |
| 某個主任務底下的次任務之間 | 那個主任務的次任務 |
| 某個次任務底下的孫任務之間 | 那個次任務的孫任務 |

- 帶著子任務一起搬：次任務升為主任務時，它的孫任務會變成次任務；主任務降為次任務時，它的次任務會變成孫任務。
- **最多三層**：如果搬過去會超過三層，例如有次任務的主任務要變成孫任務，App 會擋下並自動復原，提示要先移走哪些子任務。
- 拖曳時，還沒有子任務的地方會出現**虛線框**，可以把任務放進去。
- 不能把任務拖進它自己底下。
- 跨層級搬移後，畫面下方會出現「已把…改為…」和「**復原**」按鈕，6 秒內按「復原」可以回到搬移前。

## 完成狀態由子任務決定（v2.6 起，v2.7、v2.9 調整）

- 某個次任務底下的**孫任務全部打勾**，這個次任務會自動標示完成。
- 某個主任務底下的**次任務全部打勾**，這個主任務會自動標示完成，而且會一路往上連動：勾完最後一個孫任務時，次任務和主任務可能一起完成。
- 自動完成的項目會依 v2.5 的規則移到同一層最下方，畫面下方也會顯示提示。
- **（v2.7）還有未完成的子任務時，上層任務不能打勾**：勾選框會變淡，點了會提示「還有 N 個未完成的子任務」。
- 只要有子任務**取消打勾**，或**新增未完成的子任務**，上層會自動恢復成未完成。
- **（v2.9）上層可以手動取消勾選**：子任務都完成、上層自動打勾後，仍可以手動取消，讓它顯示「未完成」，方便繼續新增次任務。手動取消後會一直保持未完成，直到它底下的子任務有變動（打勾、新增、刪除、拖進或拖出），才恢復自動判斷。之後新增的子任務全部完成時，上層會再自動完成。
- 子任務都完成時，上層也可以再手動打勾。
- 沒有子任務的項目照常手動打勾。
- 更新到 v2.7 後第一次開啟時，App 會自動校正舊資料：「上層已勾、但子任務未完成」的任務恢復成未完成，「子任務全部完成、但上層未勾」的任務標示完成。

## 📊 總覽報表（v2.8 起）

從右上角 ⋮ →「📊 總覽報表」開啟：

- **整體完成率**：以「工作項目」計算，也就是最底層的任務：孫任務、沒有孫任務的次任務、沒有次任務的主任務。這樣自動完成的上層任務不會被重複計算。另外分別列出主任務、次任務、孫任務各完成幾項。
- **完成數**：今天、近 7 天、近 30 天各完成幾個工作項目。
- **最近 14 天每天完成數**：長條圖，點一下長條可以看那天的數字和星期。
- **各主任務進度**：每個主任務的進度條、完成數／總數、剩幾項、已進行幾天。可以依「進度低 → 高」「剩餘項目多 → 少」「建立最久 → 最新」「清單順序」排序，也可以隱藏已完成的主任務。點一下會跳到那個任務。
- **拖最久的未完成項目**：依建立時間列出最久還沒完成的 5 項，並標出所屬的主任務。
- **📋 複製報表文字**：把報表整理成文字，可以貼到 LINE 或 Email 回報。
- 沒有記錄完成時間的舊項目（v1.8 以前完成的），會算進完成率，但不會出現在每日完成數裡。

## 介面整理與深色模式（v2.10 起）

依 Hallmark 設計檢查整理介面，功能與資料完全不變：

- **深色模式**：預設跟著手機的深色／淺色設定自動切換；右上角 ⋮ 選單的「外觀」可以改成一律淺色或一律深色（v2.10.1）。深色模式下選中的按鈕有藍色外框，層次和淺色一致。
- **線條圖示**：選單和按鈕裡的表情符號圖示，換成同一套線條圖示。
- **顏色**：整理成以藍色為主的色票，灰色帶一點藍，深色模式的配色由同一組色票自動產生。
- **細節**：按鍵焦點外框、停用狀態、手機開啟「減少動態效果」時關閉動畫；報表裡的「·」分隔改成逗號與括號。

## 字體大小（v2.11 起）

- 從右上角 ⋮ →「字體大小」，按 **A−／A+** 調整，有 85%、100%、115%、130%、150% 五段。點中間的百分比可以恢復 100%。
- 字級、行距、按鈕、勾選框和間距會**一起等比例縮放**，排版不會跑掉；放大後文字太長會自動換行，不會超出畫面。
- 調整時選單不會關閉，可以邊看邊調。設定會記住，下次開啟一樣。

## 註記（v2.11 起）

- 每一項任務（主任務、次任務、孫任務）都可以加一段**註記**，例如聯絡人、電話、細節或進度說明，可以多行。
- **新增**：⋮ →「開啟修改」，每一列會出現灰色的註記圖示 📄，點一下就能輸入。輸入框旁的 🎤 可以用說的，內容會接在後面。
- **觀看**：有註記的任務，右側會一直顯示藍色的註記圖示，點一下就會跳出小視窗顯示內容和更新時間。
- 在小視窗裡可以**編輯**或**刪除註記**；把內容清空再儲存，也等於刪除。
- 註記會一起存進備份檔；跨層級拖曳搬移時，註記也會跟著任務走。

## 注意事項

- **資料存在手機裡**：APK 透過手機上的 Chrome 執行，通常會和 Chrome 開同一個網址時共用資料。但如果清除 Chrome 資料、換了網址或手機沒有 Chrome，資料就會不同。安裝 APK 前，建議先用「下載備份檔」或「複製備份文字」備份一份，必要時再還原。
- **語音輸入**：APK 實際上是由手機上的 Chrome 執行，所以語音辨識跟 Chrome 一樣需要網路；離線時會自動改用鍵盤輸入。
- **更新 App**：修改 `index.html` 後，請把 `sw.js` 第 3 行的 `worklog-v2.11` 改成新的版本號（例如 `worklog-v2.12`）再上傳，手機下次開啟時就會更新。只改網站內容不需要重新產生 APK。
- **拖曳套件**：v2.9 起 SortableJS 直接放在 App 檔案裡（`sortable.min.js`），不必連網也能拖曳。更新時請記得一起上傳這個檔案。
